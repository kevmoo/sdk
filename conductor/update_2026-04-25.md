# Update 2026-04-25: Batch I/O, `writeList`, and the "Slam Dunk"

Today's session marked the completion of the most critical performance milestone for `Socket2`: solving the event-loop thrashing that crippled concurrent stream performance.

## The Problem
Yesterday we discovered that `Socket2` achieved an amazing 1,695 RPS on straight-line benchmarks (`oha -c 1`), beating `dart:io` significantly. However, under high concurrency (`oha -c 50`), throughput collapsed to 49.9 RPS. We identified the root cause as **Event Loop Thrashing**: streaming a 1.3 MB file using 64KB chunks caused thousands of `await` boundaries between Dart and C++ per connection, bringing the isolate's task queue to its knees.

## The Solution: Batch I/O (`writeList`)
To solve this, we implemented `Socket2.writeList(List<Uint8List> buffers)`. By pooling up to 8 buffer slices at a time and sending them across the FFI boundary in a single `await` call, we minimized context switching drastically. 
The C++ layer (`Socket2_WriteList`) unpacks the Dart list and uses `SocketBase::Write` sequentially, ensuring the data is pushed to the OS kernel as quickly as possible.

### The Breakthrough: `Dart_TypedDataAcquireData`
While implementing this, we made a crucial discovery about how the Dart VM C++ API handles `TypedData` views (e.g. `Uint8List.sublistView`). The user astutely pointed out that we weren't passing `offset` or `length` from the views down to C++. We realized that `Dart_TypedDataAcquireData` natively intercepts view bounds on the C++ side! It automatically adjusts the returned memory pointer and length, completely abstracting the view slicing logic. This allows our `writeList` implementation to remain completely zero-allocation without manually passing dimension parameters.

## The Bugs Squashed
1.  **The "EOF vs EWOULDBLOCK" Hang**: During the batch testing, our unit tests hung. We discovered that in non-blocking POSIX sockets, a return of `0` bytes does not strictly mean `EOF`. On macOS, it means `EWOULDBLOCK`. We updated `_tryRead` and `_tryWrite` in `_Socket2Impl` to check the `_isClosed` flag before treating `0` as an actual socket termination, fixing the deadlocks.
2.  **TypedData to Uint8List**: To eliminate casting overhead and clarify the API, we updated `Socket2` and `bottom_shelf` to strictly deal in `Uint8List` instead of the generic `TypedData`.

## The Result
With the bugs ironed out, we recompiled the SDK (`tools/build.py -m release create_sdk`) and ran the `matrix.dart` benchmarks using the custom `dart-sdk`.

The result was a resounding success on the heavy `/stream` endpoint under 50 connections:
- `dart:io` JIT Baseline: 1454.1 RPS
- `bottom_shelf` (Socket2) JIT: **1611.4 RPS (+10.8%)**

- `dart:io` AOT Baseline: 1468.4 RPS
- `bottom_shelf` (Socket2) AOT: **1576.1 RPS (+7.3%)**

We have successfully beaten the highly optimized, C++-backed `dart:io` streams using an explicit, ownership-passing, zero-allocation asynchronous API in Dart.
